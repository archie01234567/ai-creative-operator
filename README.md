# AI Creative Operator

Takes a marketing brief and produces a 10-15 second, 9:16 social ad:

```
Brief -> Strategy (3+ angles, one selected) -> Storyboard -> Prompt builder
      -> Video provider -> Assembly (captions + brand card) -> QA -> Final asset
```

Built for the NomadGuard brief in `briefs/nomadguard.json`; any brief with the same fields works.

## Setup

Requires Python 3.12+, [uv](https://docs.astral.sh/uv/) and `ffmpeg`/`ffprobe` on PATH.

```bash
uv sync
cp .env.example .env      # add ANTHROPIC_API_KEY and GEMINI_API_KEY
```

## Run

```bash
uv run creative-operator run                       # NomadGuard brief, Claude + Gemini Omni Flash
uv run creative-operator run --brief my_brief.json # edit a copy of briefs/nomadguard.json
uv run creative-operator run --offline             # no keys: canned plan + mock video provider
uv run creative-operator status <job_id>           # state, error + hint, plan, QA (--json for raw)
uv run creative-operator resume <job_id>           # continue an interrupted / failed job
uv run creative-operator list
uv run creative-operator qa some_video.mp4         # technical QA on any file
uv run pytest
```

Each run prints its state transitions live and writes `jobs/<job_id>/`:
`job.json` (full record), `report.html` (strategy, storyboard, prompts, QA scores, sampled
frames and the video in one page), `clips/`, and `final_round<N>.mp4`.

`--offline` exercises the whole lifecycle with test-pattern clips and ends in `NEEDS_REVIEW`,
because there is no vision model to review the result and a skipped review is not a pass.

Video made by hand in another tool (Kling, Higgsfield, Runway) goes through the same assembly
and QA: `run --provider manual` plans and writes the prompts, then
`resume <job_id> --clips clip.mp4` picks the job back up.

## Architecture

```
src/creative_operator/
  models.py          Pydantic contracts: Brief, Strategy, Storyboard, Job, QA reports
  planner.py         Claude: angles + selection, storyboard; rule validation + one repair pass
  prompt_builder.py  storyboard -> provider requests (single-take or per-scene), no model call
  providers/
    base.py          VideoProvider: generate() / get_status() / get_result(), Capabilities, ErrorKind
    omni.py          Gemini Omni Flash (real)
    mock.py          ffmpeg test clips + scripted failures (tests, --offline)
    manual.py        clips generated by hand
  media.py           ffprobe, frame grabs, Pillow overlays, ffmpeg assembly
  qa.py              technical QA (ffprobe/ffmpeg) + creative QA (vision) + pass/fail gate
  pipeline.py        job state machine, retries, resume
  store.py           one JSON file per job, atomic writes
  llm.py             the single LLM seam (Claude structured outputs; fixture stand-in)
  cli.py, report.py  interface
```

**Job lifecycle**

```
CREATED -> PLANNING -> GENERATING -> ASSEMBLING -> EVALUATING -> FINALIZED
                           ^                           |
                           +--- QA-driven re-render ---+     NEEDS_REVIEW | FAILED
```

- Every transition is saved before the next side effect, and each stage is re-entrant, so
  `resume` is the same code path as `run`. Planning and finished clips are never paid for twice.
- Provider errors are classified: `transient` and `lost` are retried with exponential backoff
  (3 attempts per clip), `blocked` (safety filter) and `fatal` (auth, billing, bad request)
  stop immediately. A failed job ends in `FAILED` with the stage, kind, message and a hint.
- A job with no heartbeat for 2 minutes shows as `(stalled)` in `status` / `list`.
- `NEEDS_REVIEW` means an asset exists but QA rejected it (or could not review it) and the
  re-render budget is spent. It is deliberately not the same state as `FINALIZED`.

## Providers

| Role | Provider | Why |
| --- | --- | --- |
| Strategy, storyboard, creative QA | Claude Opus 5.5 (`claude-opus-5-5`), structured outputs | Typed objects straight into Pydantic, vision for frame review |
| Video | Gemini Omni Flash (`gemini-omni-1.2-flash`), Gemini API | Native 9:16, up to 15 s in one generation with audio, reference images, one API key |

Veo was the first choice, but the Veo 3.1 models were shut down on the Gemini API on
22 Oct 2026; Omni Flash is Google's documented replacement on the same key.

## Decisions that matter

1. **One generation for the whole spot when the provider allows it.** A 13 s storyboard is
   sent as a single request with a timed shot list. One generation gives one face, one grade
   and one audio bed, which is the cheapest defence against "unrelated AI clips stitched
   together". If a provider's clips are shorter than the spot, the prompt builder switches to
   one request per shot and passes a frame from shot 1 as an identity reference. The mode is
   chosen from `provider.capabilities`, so the pipeline does not change when the provider does.
2. **The video model never renders text.** Prompts forbid captions and logos; the opening
   caption and the brand card are drawn with Pillow and composited by ffmpeg, inside the
   area Reels/TikTok UI does not cover. A garbled brand name is the fastest way to look fake.
3. **Producibility is a strategy criterion.** Angles are scored on hook strength, sound-off
   clarity and how well current video models can actually render them, so the selection
   favours ideas that survive generation.
4. **The model scores, code decides.** Structured outputs guarantee shape, not rules:
   planner output is validated (3+ angles, real selection, 10-15 s, opening shot <= 3 s) and
   sent back once for repair. In creative QA the model lists defects first, then scores five
   dimensions; pass/fail is a fixed threshold in code (every dimension >= 6, mean >= 7).
5. **QA closes the loop once.** A rejected render is regenerated once with the reviewer's fix
   suggestions appended to the prompt, then handed to a human.

## Trade-offs

- **JSON files, in-process polling.** No queue, database or worker pool. Fine for one
  operator; the state machine and store are the parts that would stay if it grew.
- **Omni's video call is request/response**, so the adapter runs it on a thread to meet the
  async interface. An in-flight generation cannot be re-attached after a process restart; the
  job detects this (`lost`) and resubmits, which costs one extra generation.
- **Creative QA sees stills, not motion or audio.** It catches identity drift, artifacts,
  off-brief content and a weak opening frame; it cannot catch jitter, morphing between
  sampled frames or bad sound.
- **Single-take trades control for coherence.** Shot timing inside one generation is
  approximate, and one bad shot means re-rendering all of it.

## Intentionally not built

Web UI, authentication, multi-tenant job queue, cost tracking, a second real provider,
A/B variants per angle, music/voice-over generation, prompt-level safety rewriting for
`blocked` errors.

## With another day

1. Generate 2-3 candidates per job and let QA pick the best, instead of re-rendering only on failure.
2. Motion-aware QA: send the mp4 itself to a video-understanding model, plus frame-difference checks for freezes and flicker.
3. A keyframe-first flow (generate and approve a still of the protagonist, then image-to-video) for stronger identity control in per-scene mode.
4. A second provider adapter (Kling or Runway) with server-side job ids, which makes mid-generation resume free.
5. Calibrate the QA thresholds against a small set of human-rated ads.
